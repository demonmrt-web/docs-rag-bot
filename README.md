# docs-rag-bot

Бот-помощник по документации: загружаете файлы (`.md`, `.txt`, `.pdf`, `.docx`), задаёте вопрос и получаете ответ **только по этим документам**, со ссылками на источники. Всё работает локально: модели запускаются через Ollama, данные никуда не уходят.

Сделано вместе с Claude Code: я ставил задачи и проверял результат, код писали и дорабатывали вдвоём с ИИ-ассистентом.

## Зачем

Типовая задача внедрения ИИ в компании: сотрудники или клиенты спрашивают по регламентам, инструкциям, базе знаний, а модель «фантазирует». Здесь модель отвечает по найденным фрагментам, а если в документах ответа нет, **она не вызывается вообще**, и бот честно говорит «ответа нет».

## Как устроено

```
вопрос ─▶ n8n (webhook) ─▶ API (FastAPI) ─▶ вектор вопроса (Ollama, bge-m3)
                                              │
                                  поиск похожих кусков в Qdrant
                                              │
                      нет похожих ──▶ «ответа нет» (модель не вызывается)
                      есть ─────────▶ Ollama (qwen2.5) отвечает по кускам со ссылками [1], [2]
```

| Часть | Что делает |
|---|---|
| `app/chunking.py` | Режет текст на куски по абзацам и предложениям с перекрытием |
| `app/loaders.py` | Читает `.md`, `.txt`, `.pdf`, `.docx` |
| `app/ollama.py` | Клиент Ollama: векторы и ответ |
| `app/store.py` | Хранилище векторов: файлы на диске для разработки или Qdrant на сервере |
| `app/rag.py` | Загрузка документов и ответ с источниками |
| `app/main.py` | HTTP-API: `/ask`, `/ingest`, `/reindex`, `/sources`, `/health` |
| `n8n/workflow_ask.json` | Рабочий процесс n8n: webhook → API → ответ |
| `eval/` | Набор вопросов и скрипт оценки качества |

## Запуск через Docker

```
docker compose up -d --build
docker compose exec ollama ollama pull bge-m3
docker compose exec ollama ollama pull qwen2.5:3b
curl -X POST http://localhost:8000/reindex
curl -X POST http://localhost:8000/ask -H "Content-Type: application/json" -d "{\"question\": \"Какую модель Whisper использует приложение для субтитров?\"}"
```

Сервисы: API `:8000`, n8n `:5678` (импортируйте `n8n/workflow_ask.json`, затем POST на `/webhook/ask` с `{"question": "..."}`), Ollama `:11434`, Qdrant `:6333`. Видеокарта NVIDIA используется автоматически; без неё удалите блок `deploy` у сервиса `ollama`.

Документы для примера лежат в `docs/` (описания моих проектов). Свои файлы можно загрузить через `POST /ingest`.

## Запуск без Docker

```
pip install -r requirements.txt
set VECTOR_STORE=local
python -m app.cli ingest docs/
python -m app.cli ask "На сколько процентов должна подорожать монета, чтобы бот начал следить за максимумом?"
uvicorn app.main:app
```

Нужна запущенная Ollama с моделями `bge-m3` и `qwen2.5:3b`. Другие модели задаются переменными `LLM_MODEL` и `EMBED_MODEL`.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `LLM_MODEL` | `qwen2.5:3b` | модель для ответа |
| `EMBED_MODEL` | `bge-m3` | модель для векторов |
| `VECTOR_STORE` | `local` | `local` или `qdrant` |
| `CHUNK_CHARS` / `CHUNK_OVERLAP` | 800 / 150 | размер куска и перекрытие |
| `TOP_K` | 4 | сколько кусков отдаётся модели |
| `MIN_SCORE` | 0.35 | порог сходства: ниже — «ответа нет» |
| `API_KEY` | пусто | если задан, нужен заголовок `X-API-Key` |

## Тесты и оценка качества

```
pip install -r requirements-dev.txt
pytest                      # быстрые тесты без Ollama: нарезка, индекс, цепочка вопрос-ответ
python eval/run_eval.py     # 12 вопросов по документам: нужен ли файл в источниках и ключевое слово в ответе
```

`pytest` проверяет нарезку, обновление и удаление документов, сохранение индекса после перезапуска и отказ на нерелевантный вопрос. Результаты оценки на реальных моделях см. в разделе ниже.

## Результаты оценки

Прогон на Windows, RTX 2060 (6 ГБ), Ollama 0.40, `bge-m3` + `qwen2.5:3b`, `VECTOR_STORE=local`, 3 документа (14 кусков):

- **12 из 12** вопросов: на 10 вопросов по документам правильный файл в источниках и ключевое слово в ответе, на 2 вопроса вне документов (столица Франции, цена подписки) бот отказал.
- Скорость: 3–13 секунд на вопрос; первый запрос 82 секунды (холодная загрузка модели в память видеокарты).

Что стоит знать об этой цифре:
- Первый прогон дал 11 из 12: на вопрос про цену подписки модель сама ответила «ответа нет», но мой критерий требовал, чтобы она вообще не вызывалась. Я исправил критерий: теперь допустим отказ и без модели, и отказ самой модели. Поведение бота при этом не менялось.
- Проверка «ключевое слово есть в ответе» грубая: она не ловит неточные пересказы. Например, на вопрос про режим со сценарием маленькая модель написала, что бот «пропускает слова, которые не совпадают», а в документации это сформулировано иначе. Поэтому источники всегда показываются.
- Вопросов мало (12) и они написаны по тем же документам, поэтому это проверка работоспособности, а не оценка качества на реальной базе знаний.
- Запуск в Docker на этой машине не проверялся (см. раздел «Честно о границах»).

## Честно о границах

- Это учебно-портфолио проект, а не промышленная система: нет авторизации пользователей, очереди задач, мониторинга.
- Качество зависит от выбранных моделей. Маленькая модель (3B) иногда ошибается в формулировках, поэтому в ответе всегда показаны источники.
- Нарезка текста простая (по абзацам и предложениям). Таблицы и сканы PDF без текстового слоя не распознаются.
